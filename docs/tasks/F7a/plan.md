## Understanding

Responsible gaming still runs on the in-repo mock: the limits are `useState` in one browser (a limit that
lives in one tab is not a limit), a break is a mock flag holding a placeholder end ("Wed 30 Sep, 14:00"),
and the page shows a "This month" card with invented figures. F7a moves all of it onto the account: the
deposit, stake, loss and time limits come from `GET /v1/me/limits` and change through `PUT`, where the
API decides whether a change applies at once (a decrease) or waits (an increase, shown pending with the
API's effective time). Taking a break or self-excluding is asked once in full sentences and sent as
`POST /v1/me/self-exclusion`; the API revokes every session, so the player ends up signed out, shown the
end date the API gave. Whether a break is in force is read from `/v1/me` (`flags.excluded_until`), so the
banner, the locked slip and the paused deposits are server state a reload cannot end. The wallet's
deposit-limit card comes back with the API's `used` and `amount`.

## Design

**Contract → loader → mapper → route → api → hook → components**

- `src/lib/server/responsible-gambling.ts` (server only), tag `Responsible gambling`, every call through
  `withSession`:
  - `loadLimits(ctx, session)` → `GET /v1/me/limits` → `toLimits(items)`.
  - `changeLimit(ctx, session, change)` → `PUT /v1/me/limits` with `toLimitSet(change)` → `toLimit`.
  - `selfExclude(ctx, session, request)` → `POST /v1/me/self-exclusion` with `toSelfExclusionRequest` →
    `toExclusion`.
- `src/lib/api/mappers/responsible-gambling.ts` (pure): `toLimits` (a type or period the contract adds
  later is left out, as payment methods), `toLimit` (absent `amount`, `minutes`, `used`, `pending` →
  `null`), `toLimitSet` (only the field that applies), `toSelfExclusionRequest`, `toExclusion`.
- Route handlers: `src/app/api/me/limits/route.ts` (`GET`, `PUT` → 200 with the API's limit) and
  `src/app/api/me/self-exclusion/route.ts` (`POST` → 201 with the exclusion; `clearSessionCookie` on
  success). Gates as decision 17.
- `src/lib/api/schemas.ts`: `rgLimitSchema`, `rgLimitsSchema`, `limitChangeSchema` (strict; money above
  zero or minutes 1–999999), `selfExclusionRequestSchema` (strict), `exclusionSchema` — each
  `satisfies z.ZodType<Domain>`; `responsibleGamingStatusSchema` goes.
- Domain types `src/features/responsible-gaming/types.ts`: `LimitType` (`deposit | stake | loss |
session_minutes`), `LimitPeriod` (`day | week | month`), `RgLimit { type, period, amount, minutes,
effectiveFrom, used, pending: { amount, minutes, effectiveFrom } | null }`, `LimitChange` (money:
  `{ type, period, amount }` | time: `{ type: "session_minutes", period, minutes }`),
  `ExclusionKind`, `ExclusionDuration`, `SelfExclusionRequest`, `Exclusion { kind, startsAt, endsAt }`,
  `Break { until: string | null }`.
- `src/lib/query/keys.ts`: `rgKeys.limits()` under `rgKeys.all` (already in `forgetPlayer`).
- `src/lib/api/client.ts`: `apiClient.put` (CSRF header, as every non-GET).
- `src/lib/money.ts`: `percentOf(part, whole)` — a whole percentage for a bar, display only.
- Browser API `src/features/responsible-gaming/api/limits.ts` (`getLimits`, `changeLimit`) and
  `api/self-exclusion.ts` (`selfExclude`, a 30 s deadline as the money POSTs); `api/status.ts` goes.
- Pure lib `src/features/responsible-gaming/lib/`: `breakOf(player)` (decision 2), `limitFor`,
  `openingPeriod`, `limitInput(type, raw)` → a `LimitChange` value or why not (decision 5),
  `exclusionOutcome(error)` (refused / unanswered / session).
- Hooks `hooks/use-responsible-gaming.ts`: `useBreak()` (from `useSession`), `useLimits(enabled)`
  (staleTime 30 s, read again on focus — a limit set on another device shows when the player comes back),
  `useChangeLimit()` (invalidates `rgKeys.limits()`), `useSelfExclude()` (decision 6; a ref so one
  `POST` per Confirm). `lib/i18n/use-long-date-time-text.ts`: `useLongDateTimeText()` (decision 11).
- Components: `ResponsibleGamingView` (states, decision 13), `LimitsSection` (new: loading / failed /
  the four cards), `LimitCard` (rewritten on `RgLimit` strings), `BreakStarted` (new), `ChoiceTiles`
  (four tiles in two rows); `StatusBanners` (`CoolOffBanner` from `useBreak`, the permanent line);
  `use-odds-locked`; `SystemOverlays` (Take a break → the page; the `limit` dialog per question 2).
- Slip: `CtaAction` gains `paused`; `resolveCta(totals, isGuest, paused)`; `useBetSlip` passes
  `useBreak() !== null`; `PlaceBetButton` labels it; `SlipAlerts` shows the break line (one message
  with a break refusal); `use-place-bet` re-reads `rgKeys.all` after a ticket and after no answer.
- Wallet: `DepositLimitCard` (new) in `WalletHome`; Deposit off during a break with the reason
  (`aria-describedby`); `DepositFlow` shows `DepositPaused` (new) instead of a new deposit during a
  break; `use-payments` `moneyArrived` re-reads `rgKeys.all`.
- Mock: the repository's RG status and break go (`ResponsibleGamingStatus`); `SYSTEM.coolOff` goes;
  `env.useMocks`' comment names session activity only (F7b).
- Errors handled: `PUT` 422 (any code) → "Your limit wasn't saved" + the API's title and `detail`; no
  answer → "We couldn't save your limit" (a retry is the same `PUT`, which sets the same value); 401 →
  `/api/me` read again. Self-exclusion: decision 8. The RG refusals: decision 10.
- i18n: `rg.*` (limit cards, used, pending, saved, refusals, guest, failed, started, 5 years, confirm
  bodies), `system.excludedTitle` / `excludedBody`, `wallet.depositLimit`, `wallet.manage`,
  `wallet.noDepositLimit`, `wallet.setLimit`, `wallet.depositLimitFailed`, `wallet.depositsPaused*`,
  `betSlip.paused`; removed: `rg.thisMonth`, `deposited`, `netLoss`, `monthSummary`, `activeBreak`,
  `activeExclusion`, `saved` (and `system.limit*` per question 2). Composed Amharic in
  `TRANSLATION-NOTES.md`.
- No feature flag: this is Release 1 (RG-01–RG-03 are must-haves).

## Risks

- **Money and protection**: limit amounts stay the contract's strings end to end; the only arithmetic is
  the bar's display percentage in `lib/money.ts`. Nothing decides whether a change is an increase: the
  API's answer is shown. No limit or break is kept in the browser; the break is read from `/api/me`, so a
  reload, another tab or another device can't end it, and no clock in the browser ends it early. The
  self-exclusion is irreversible: asked once in full sentences, one `POST` per Confirm, the copy checked
  against RG-02 and C12 (question 1). The slip's and the deposit's refusals are unchanged.
- **Security**: two mutating route handlers with the existing gates (origin, CSRF header, JSON, 4 KiB
  strict bodies, the session); `PUT` is never CORS-simple; `no-store`; `Prefer` in `next dev` only; the
  session cookie cleared once the API has revoked it.
- **Personal data**: limits under `rgKeys`, dropped on every session change (tested); a break started
  drops every cache as a logout does.
- **Accessibility**: the confirmation is an `alertdialog`; the tiles a radio group; save and break
  answers `role="status"` (refusals `role="alert"`); focus goes to the started screen's heading; the
  wallet's off Deposit names its reason (`aria-describedby`); 44 px targets; no `uppercase` or
  `tracking-*` on labels (the page's "This month" label had both; it goes).
- **Performance**: one small read of the limits on the wallet and the RG page (30 s, on focus), and after
  a bet, a completed deposit or an RG refusal.

- Refusing login to a self-excluded player (the API's; RG-02 allows login to withdraw).
