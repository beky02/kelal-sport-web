Before planning: `pnpm check` passed on main (1,649 tests); `pnpm contract:sync --check` found
`docs/backend/engineering-decisions.md` behind (one new open question, dead heats, nothing for F8cc). With

## Understanding

A customer at the shop kiosk taps **Get code**. The kiosk turns the slip on screen into an 8-digit slip
code (`POST /v1/retail/slip-codes`), signed by the PC's device key over the exact body, and shows it full
screen: `4829 1735` in large type, a QR of `qr`, and how long it is valid. After `code_display_seconds`
(60) the screen starts over for the next customer. Separately, 90 s (`idle_reset_seconds`) without a touch
also starts it over. Starting over clears the slips, the filters (the URL) and the language, and stops the
price polling until someone touches the screen. The terminal may make 30 codes per 10 minutes. A 429 says
when the next code can be made (`Retry-After`), and Get code waits until then. Every other refusal says
what to change (a 422's fix), or lets the terminal's status decide (401, a closed shop).

## Design

```
Get code ─▶ slipCodeRequestFrom(slip)            features/terminal/lib/slip-code.ts (pure)
          ─▶ useGetCode: key per intent           hooks/use-slip-code.ts (kiosk store: codeIntent, pausedUntil, shownCode)
          ─▶ createSlipCode(request, key)         api/slip-codes.ts: toSlipCodeCreate → JSON text → signRequest(TERMINAL_CALLS.slipCodes)
          ─▶ POST /api/terminal/slip-codes        app/api/terminal/slip-codes/route.ts
               terminal host → same origin + JSON → activated terminal (cookie) → Idempotency-Key (UUID)
               → device signature (shape, ±20 s clock) → body (≤ 16 KiB, UTF-8, strict SlipCodeCreate)
          ─▶ createSlipCode(ctx, session, device, text, key)   lib/server/terminal.ts
               POST /v1/retail/slip-codes: token, X-Device-Id (cookie), timestamp, signature, Idempotency-Key, the text as read
          ◀─ 201 SlipCodeCreated → toSlipCodeReceipt (mapper; mock-only expiry) → slipCodeReceiptSchema (browser)
          ◀─ Problem passed through (respond: code, errors[], Retry-After)
```

- **Contract operations:** `createSlipCode` (`POST /v1/retail/slip-codes`). `getTerminalSelf` is unchanged,
  and its `idle_reset_seconds` and `code_display_seconds` are already mapped.
- **Domain types** (`features/terminal/types.ts`): `SlipCodeRequest { betType, systemSizes, legs:
{ outcomeId, odds }[], stakeHint: string | null }`; `SlipCodeReceipt { code, display, expiresAt, qr }`.
- **Mappers** (`lib/api/mappers/terminal.ts`, pure, used in the browser too): `toSlipCodeCreate(request)`
  (domain → contract, keys in the contract's order, `system_sizes` and `stake_hint` left out when empty)
  and `toSlipCodeReceipt(created)`. Both are tested against the contract's own request and response
  examples.
- **Schemas** (`lib/api/terminal-schemas.ts`): `slipCodeCreateSchema`, strict, `satisfies
z.ZodType<SlipCodeCreate>` (the route's input check). `slipCodeReceiptSchema satisfies
z.ZodType<SlipCodeReceipt>` (the browser's check of the route's answer): code `^\d{8}$`, `qr` 1–2,048
  characters.
- **Calls table** (`features/terminal/lib/calls.ts`): `slipCodes: { route: "/api/terminal/slip-codes",
method: "POST", api: "/v1/retail/slip-codes", signed: true }`. `terminalRequest` gains an
  `idempotencyKey` option.
- **Body reading** (`lib/server/body.ts`): `readText(request, cap)` returns the bounded raw text (strict
  UTF-8) or `"too_large"`. `readJson` is built on it, with its behaviour unchanged.
- **No query keys added.** A mutation (`mutationKey: [...terminalKeys.all, "slip-code"]`) never touches
  money, a balance or a bet, so it invalidates nothing. A 401, a closed shop or a device refusal
  invalidates `terminalKeys.status()`.
- **Kiosk store** (`features/terminal/stores/kiosk.store.ts`), client state, never persisted:
  - `chosen`, as today;
  - `idle: boolean`;
  - `round: number`, the page's key, which `startOver` raises;
  - `codeIntent: { signature, key } | null`;
  - `shownCode: { receipt, slip: number } | null`;
  - `codesPausedUntil: number | null`.

  `reset()` (language) is kept for tests and `startOver`.

- **Hooks:**
  - `useStartOver()` (decision 8);
  - `useIdle({ idleMs, paused })` (decision 9): document listeners, one timer re-armed on activity,
    `idle` in the store, and the price queries invalidated on waking;
  - `useGetCode()` (decisions 5, 6, 10, 12).
- **Components:**
  - `Kiosk` mounts `useIdle` and the code screen, and keys the page by `round`.
  - `KioskSlip` replaces `BookBet` with `GetCode` (decision 1): the button, then its message (the wait,
    or the refusal with its fix).
  - `SlipCodeScreen`: a Radix dialog over the whole kiosk, with:
    - the title "Your code";
    - `display` at about 64 px (44 px on a phone);
    - the QR (`QrCode`, about 240 px);
    - "Valid until Thu 8 Oct, 22:36" (`useValidUntil`, EAT);
    - "Take this code to the counter.";
    - "This screen clears in {seconds} s." (visual only, not announced each second);
    - Done, which has focus.

    Escape is Done.

  - `components/ui/QrCode.tsx`: the QR as one SVG path, with `role="img"` and a label, and a 4-module
    quiet zone. The encoder is loaded with `import()`.
  - `lib/qr.ts`: `qrModules(text)` and `qrPath(modules)`, pure.
- **Chrome:** `SportsbookChrome.pricePollMs` → `usePricePollMs()` (decision 9). `useBoard` and `useEvent`
  call it. The player's value is unchanged.
- **Error codes handled:** decision 10's table, in `slipCodeRefusal(error, request)` (pure, in
  `lib/slip-code.ts`), which returns the message key, any stake fix, the picks to close, and whether the
  status must be read again.
- **i18n keys** (proposed copy; Amharic composed and listed in `TRANSLATION-NOTES.md`):

  | Key                         | English                                                                   |
  | --------------------------- | ------------------------------------------------------------------------- |
  | `terminal.code.get`         | Get code                                                                  |
  | `terminal.code.title`       | Your code                                                                 |
  | `terminal.code.take`        | Take this code to the counter.                                            |
  | `terminal.code.clears`      | This screen clears in {seconds} s.                                        |
  | `terminal.code.qr`          | QR code for {code}                                                        |
  | `terminal.code.paused`      | This terminal has made too many codes. Get code is back in {minutes} min. |
  | `terminal.code.pausedLater` | This terminal has made too many codes. Try again later.                   |
  | `terminal.code.failed`      | Couldn't get a code. Try again.                                           |
  | `terminal.code.cannot`      | This slip can't be made into a code as it is.                             |

  These are reused as they are:
  - `betSlip.done`, `booking.validUntil` and `terminal.closed.title`;
  - `betSlip.errors.stakeTooLowBody` / `stakeTooHighBody` and `betSlip.setMax` ("Set {amount}");
  - the slip's `suspendedAlert`.

  `betSlip.bookBet` stays for the player.

- **Feature flags:** none new. Release 2 stays off.

## Risks

- **Money.**
  - The code stores picks and a stake hint only. Nothing is placed, and the counter re-prices at sale
    (C19 §4.3, §14).
  - The slip's figures are F8cb's (slipcalc on `retail_betting`), unchanged.
  - The stake hint goes only when slipcalc accepts it (`bookingRequestFrom`), and a refused hint offers
    the server's limit, never a computed one.
  - Odds and money stay decimal strings end to end; no `Number` in arithmetic.
  - The first tap after idle may land on a price older than 30 s, before the refresh arrives. The
    engine's price is the one that counts (D1), and the POS shows old → new.
- **Security** (`security-reviewer`). The new route checks, before any call:
  - the host, the origin (CSRF header and JSON), the session cookie and the key;
  - the signature's shape and clock;
  - the body: bounded, strict UTF-8, strict schema, ASCII.

  It forwards no `Prefer` outside `next dev` and never to the real API, adds `X-Device-Id` from the
  sealed cookie only, and answers `no-store`. `Retail - terminal` stays out of `API_REAL_TAGS`. The QR is
  drawn from a matrix: no markup from the API reaches the DOM. Removing Book bet's mirror shrinks the
  surface. A new dependency means supply-chain exposure: `qrcode` is pinned by the lockfile, used in the
  browser only for its matrix, and its CLI dependencies are never bundled.

- **Accessibility.**
  - The code screen is a modal dialog: a title, focus on Done, Escape closes it.
  - The QR is an image with a label, and the code is text.
  - The countdown is not announced each second.
  - The wait message is announced once (`role="status"`).
  - Targets are at least 48 px, labels at least 12 px in the body font, and Amharic is never uppercased.
- **Performance.** The encoder is loaded only with a code. Idle stops price polling. Starting over
  re-makes the page from the cache (no skeleton for the home board when it is cached). The idle
  listeners are passive and re-arm one timer.
- **Rendering identity.** `usePricePollMs` is a stable hook reference from a static chrome, so the board
  and its rows re-render no more than before (`realtime.test.ts`, `SportsbookChrome.test.tsx`).

## Out of scope

- Selling a code at the counter (F9, `kelalsport-ops`); loading a slip code on the kiosk.
- Signed catalogue reads, and the shop's own prices (request 015 part 1).
- Keeping the 429 wait across a reload; an attract screen while idle; printing or sending a code.
- Checking the signature itself (the API holds the public key) and a hardware scanner test (a gap).
- The player's Book bet, unchanged.

None. The estimate is about 1,600 changed lines, half of them tests, all on one flow (Get code, its
screen, and starting over). Splitting the idle reset off would split AC-1, which needs both.
