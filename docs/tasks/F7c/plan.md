# F7c — plan

Plan gate: approved 2026-10-09 (mode: interactive) — plan approved as written, split included; decision
12's fallback lines approved (granted → "Code accepted."; pending_deposit → "Code accepted. It applies to
your next deposit." with Deposit).

F7c is split (see **Sub-tasks**). This plan covers **F7ca — promotions** (AC-11, AC-12), built on this
branch. F7cb (the inbox, AC-13) gets its own plan when it starts; the decisions below that name the inbox
are recorded so it starts from them.

## Understanding

Players have no promotions or inbox screen today: nothing reads `Promotions` or `Inbox`, and the wallet
only shows a bonus balance. F7ca adds a Promotions page. Anyone sees the tenant's current offers from
`/v1/promotions`. A signed-in player also sees their active bonus — the API's amount, how much has been
wagered of how much is required, and when it expires — and their free bets with their conditions, from
`/v1/me/bonuses`. They can type a promo code and redeem it through `POST /v1/promo-codes/redeem`: one
`Idempotency-Key` per intent, sent again unchanged when a try had no answer, and the API's refusals
(`PROMO_INVALID`, `PROMO_ALREADY_USED`) said in words. Nothing about bonuses is computed in the browser;
a granted code re-reads the bonus, the wallet and the history from the server.

## Design

**Contract operations** (tag `Promotions`): `listPromotions` (public, `Accept-Language`),
`getMyBonuses` (`playerAuth`), `redeemPromoCode` (`playerAuth`, `Idempotency-Key`).

**Server** — `src/lib/server/promotions.ts`:

- `loadPromotions(ctx)` → `upstream("Promotions", ctx).GET("/v1/promotions")` with the UI's language, no
  authorization (`security: []`), `unwrap` → `toPromotions(items)`.
- `loadMyBonuses(ctx, session)` → `withSession` + `GET /v1/me/bonuses` → `toMyBonuses`.
- `redeemPromoCode(ctx, session, code, key)` → `withSession` + `POST /v1/promo-codes/redeem` with
  `params.header["Idempotency-Key"]` and `{ code }` → `toRedeemResult`.

**Mappers** — `src/lib/api/mappers/promotions.ts` (pure, tested on the contract's examples):

- `toPromotions(items)` → `Promotion[]`: `{ id, title, summary, terms: string | null, imageUrl: string |
null (https only), startsAt, endsAt, requiresCode }` (`terms_md` empty → null; `code` dropped).
- `toMyBonuses(b)` → `{ active: ActiveBonus | null, freeBets: FreeBet[] }`; `ActiveBonus = { id, title:
string | null, amount, wageringRequired, wageringDone, expiresAt }` (Money strings unchanged);
  `FreeBet = { id, stake, minLegs, minLegOdds: string | null, minTotalOdds: string | null, expiresAt }`.
- `toRedeemResult(r)` → `{ result: "granted" | "pending_deposit", message: string | null }`.

**Route handlers** (thin, `respond()`, `no-store`, Prism's `Prefer` only under `next dev`):

- `GET /api/promotions` — no session needed; none sent.
- `GET /api/me/bonuses` — a session for this tenant, else 401 `AUTH_TOKEN_EXPIRED`, nothing sent.
- `POST /api/promo-codes/redeem` — `assertSameOrigin` (origin + CSRF header + JSON), `Idempotency-Key` a
  UUID (else 400), body `{ code }` 1–32 chars strict (`readForm`, 4 KiB; else 422/413), a session (else
  401); answers 200 with the result or the API's Problem unchanged.

**Browser** — `src/features/promotions/`:

- `api/promotions.ts`: `getPromotions`, `getMyBonuses`, `redeemPromoCode(code, key, signal)` (30 s
  deadline, as deposits), each validated by `src/lib/api/promotion-schemas.ts` (`satisfies
z.ZodType<Domain>`).
- `lib/redeem.ts`: `redeemOutcome(error)` → `unanswered | session | refused` (deposits' rule, minus the
  payment codes) and `redeemNotice(error)` → message keys and fix per code (decision 11).
- `stores/promo.store.ts`: the open intent `{ owner, code, key, state: "sending" | "unanswered" }`.
- `hooks/use-promotions.ts`: `usePromotions()` (`promotionKeys.offers(lang)`), `useMyBonuses()`
  (`bonusKeys.mine()`; rendered only for a player), `useRedeemPromoCode(owner)` → `{ open, sending,
unanswered, answer, redeem(code, { onRefused }), dismiss }` — the answer is kept in `promo.store.ts`
  (`last`), so one that lands while the player is away is shown when they come back; on success and on no
  answer invalidates `bonusKeys.all`, `walletKeys.all`, `transactionKeys.all`; on `RG_*`
  `sessionKeys.me()` and `rgKeys.all`; on 401 `sessionKeys.me()`.
- `components/PromotionsView.tsx` (page body: heading, `MyBonusSection` or the guest prompt, `Offers`),
  `MyBonusSection.tsx` (active bonus card with `UsedBar`-style bar; free bets; loading, empty, couldn't
  load + Try again), `PromoCodeForm.tsx` (labelled field, Redeem, outcome `role="status"`/`role="alert"`,
  Try again, Deposit/Verify fixes), `OfferCard.tsx` (image, title, summary, dates, needs-a-code, Terms).
- Page `src/app/(player)/promotions/page.tsx` in `SportsbookShell` + `Card`, metadata title.

**Shared changes**: `routes.promotions = "/promotions"`; `promotionKeys`, `bonusKeys` in
`lib/query/keys.ts`; `forgetPlayer` drops `bonusKeys.all`; `MainNav` adds Promotions when
`features.bonuses`; `ProfileView` adds the Promotions row; `MobileTabBar.tabFor` maps `/promotions` to
Menu; `PublicConfigView.features.bonuses` (mapper, schema).

**Query keys**: `["promotions", "offers", lang]`; `["bonuses", "mine"]`.

**i18n** (en + am, `promotions.*` namespace, plus `nav.promotions`): heading and intro; my bonus (title
fallback, amount, wagered line, expires, none); free bets (stake line, picks, leg odds, total odds,
expires, none); code form (label, placeholder, Redeem, Redeeming…, Try again, the outcome lines of
decisions 11–12, Deposit, Verify, Enter code); offers (dates, needs a code, Terms, none, couldn't load);
guest prompt; couldn't-load lines. Composed Amharic (the wagered line, the free-bet conditions, the date
ranges) listed in `TRANSLATION-NOTES.md`.

**Feature flags**: none of Release 2's. The tenant's `features.bonuses` hides the entry points.

## Risks

- **Money.** Nothing is computed but the bar (`percentOf`, BigInt santim, FD4); no "left to wager". No
  optimistic grant: after `granted` the wallet, history and bonus are read again. The key rule (decision 10) and its limit after a reload are written down; the API's one-per-player rule is the backstop. The
  money-reviewer runs (`touches_money: true`).
- **Security.** Three route handlers: session on the two personal ones, CSRF + UUID key + strict small body
  on the POST, `no-store`, `Prefer` only under `next dev` — each with a test. The image is https only, no
  referrer; terms are text, never HTML; every `href` is a `routes.*` value.
- **Accessibility.** The code field is labelled; the outcome is `role="status"` (success) or `"alert"`
  (refusal); focus goes back to the field on a refusal; the bar has its figures in text; targets ≥ 44 px;
  Amharic without uppercase or tracking.
- **Performance.** Images lazy, fixed box, off in data saver; offers cached 5 min per language; no polling.

## Out of scope

The inbox and its badge (F7cb). Betting with bonus money or a free bet (`use_bonus`, `free_bet_id`).
Forfeiting a bonus (BON-07; no contract operation). Markdown rendering of terms (F7d). A link from the
wallet's bonus line to the page (follow-up). Push notifications.
